# WWII Unit Locations

An open, claim-based dataset of where World War II units were, when, and how sure we are. Each row is one sourced claim: *this unit was at this place on this date*, with coordinates, a precision radius, a confidence score, an event type, what the unit was doing, and the sources. Competing claims are kept as separate rows instead of being averaged away.

**Status: work in progress.** The dataset covers the **Western Front, 6 June to 31 December 1944**: 566 claims about 114 units out of 354 in the unit table (the rest are placeholders). Coverage is uneven. June 1944 (Normandy landings through the fall of Cherbourg and Operation Epsom) covers US, British, Canadian and German units, including battle groups (Kampfgruppen) and a combat command; July to December 1944 covers US Army army groups, armies, corps and selected division milestones. Rows are event-based, not daily: a unit has a row on days when something substantial happened, so its position between rows is unknown. See [docs/roadmap.md](docs/roadmap.md) for known gaps and the scale-up plan, and [docs/coverage.md](docs/coverage.md) for current counts.

## Layout

```
data/claims/<nationality>/<unit_id>.csv   master copy: one file per unit, all claim columns
data/units.csv                            unit table (one row per unit, including placeholder and parent-only units)
data/references.csv                       GENERATED table of every source cited (one row per reference, with a link, licence and claim count); curated metadata in data/references_meta.csv
schema/                                   machine-readable schema + vocabularies + human-readable README
scripts/                                  validate.py, check_coordinates.py, audit_command_location.py, audit_temporal_relationships.py, who_controls.py, build.py, build_references.py, promote_placeholders.py, migrate_campaign.py, split_from_flat.py, migrate_parent_formation.py (standard library only)
build/                                    GENERATED combined outputs (all_claims.csv, claims.geojson, coverage.csv, command_relations.csv, claim_references.csv, unit_references.csv; docs/coverage.md and data/references.csv are generated too)
docs/                                     methodology, sources, roadmap, coverage (generated); docs/review/ holds the review notes
archive/v5_flat/                          the flat CSVs the per-unit files were first split from
(repository root) .github/workflows/validate.yml   CI for pull requests and pushes to any branch; runs the commands below inside WorldWar2/
```

**Edit `data/` only. Never hand-edit `build/`**: it is generated by `scripts/build.py` and committed so people can download the combined files without running anything.

## Data model

- **Claim** (a row in `data/claims/...`): `claim_id` (never reused), optional `conflict_group_id`, `claim_status` (preferred / alternate / disputed), `unit_id`, `date`, `theater`, place (`latitude`, `longitude`, `location_name`, `location_represents`, `precision_km`), `event_type` and `current_activity`, `engaged_with`, command (`parent_unit_id` for the operational parent, `command_relationships` as a JSON list with organic, attached, operational-control or reserve links, `commander`, `composing_units`), `strength_status` and optional `strength_json`, `confidence`, `source`, `notes`. Full column definitions: [schema/README.md](schema/README.md).
- **Unit** (a row in `data/units.csv`): `unit_id`, `unit_name`, `nationality`, `echelon`, `branch`, `theater` (primary), `parent_unit_id` (organic parent of battle groups), `parent_only`, `record_status` (placeholder / partial / active), optional `formed_date` and `initial_parent_*` listing columns (see [docs/methodology.md](docs/methodology.md), "Placeholder units"). Most of the table is placeholders; [docs/coverage.md](docs/coverage.md) shows what has claims.
- **Conflict group**: claims that disagree about the same unit and event (for example two sources dating a commander's death differently). One may be preferred; the others are alternate or disputed.
- **theater**: controlled vocabulary (`western_europe`, `mediterranean`, `north_africa`, `eastern_front`, `pacific`, `cbi`, `atlantic`, `other`). All current rows are `western_europe`.

## Quick start

Requires Python 3.8+ and nothing else (standard library only). Run the commands from this directory (`WorldWar2/` in the repository).

```bash
python scripts/validate.py          # exit code 0 = data is valid
python scripts/build.py             # regenerate build/ (all_claims.csv, claims.geojson)
python scripts/build.py --check     # exit code 1 if build/ is stale (used by CI)
python scripts/check_coordinates.py # coordinate warnings only (add --geocode before a release)
```

Use the data directly: `build/all_claims.csv` (all claims, one file) or `build/claims.geojson` (Point features for GIS tools, `geojson.io`, QGIS, Leaflet).

Example (Python, no libraries):

```python
import csv
rows = list(csv.DictReader(open("build/all_claims.csv", encoding="utf-8")))
d13 = [r for r in rows if r["date"] == "1944-06-13" and r["claim_status"] == "preferred"]
print(len(d13), "preferred claims on 13 June 1944")
```

## Contributing

Every row needs a source, conflicting claims become separate rows, and nothing is invented. Read [CONTRIBUTING.md](CONTRIBUTING.md) (how to add a unit or a claim, the PR checklist) and the [code of conduct](CODE_OF_CONDUCT.md). Pull requests run `scripts/validate.py` and check that `build/` is up to date.
